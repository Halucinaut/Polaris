# M1: 0.6B Math SFT

## 总目标

在 Qwen3-0.6B 上完成第一组可复现 Math SFT，使模型学会目标推理格式，并验证训练、评估、日志、样例审阅闭环能支撑后续 DPO/GRPO。

M1 不是追求数学能力大幅提升。0.6B、LoRA、本地训练、短周期数据子集下，最重要的是建立稳定训练证据：loss 下降、格式遵循提升、基础评估不退化、样例变化能解释。

## 禁止事项

- 不做 DPO、GRPO、PPO
- 不做 Tool-call
- 不做多数据集混合
- 不做 4B/8B 训练
- 不追求 benchmark SOTA
- 不把失败 run 手工改成 completed

## 指标

| 指标 | 说明 |
|---|---|
| train_loss | 训练 loss 曲线 |
| eval_loss | 验证 loss |
| format_adherence | `<think>` 格式遵循率 |
| answer_extraction_success | 答案抽取成功率 |
| pass_at_1 | 答案正确率 |
| avg_completion_length | 平均生成长度 |
| invalid_output_rate | 无效输出比例 |
| tokens_per_sec | 训练吞吐 |
| peak_memory | 峰值内存 |
| checkpoint_size | 检查点大小 |
| wall_time | 总耗时 |

## 核心产物

| 产物 | 路径 |
|---|---|
| SFT 数据集 | `data/math/splits/sft_v1.jsonl` |
| 数据清单 | `data/math/manifest.yaml` |
| Baseline run | `runs/{baseline_run}/` |
| Sanity run | `runs/{sft_sanity_run}/` |
| 完整 SFT run | `runs/{sft_full_run}/` |
| 实验笔记 | `docs/experiment_notes/m1_math_sft.md` |
| 硬件报告 | `docs/hardware_reports/m1_sft_0_6b.md` |

## 退出标准

1. Qwen3-0.6B baseline eval 完成。
2. `sft_v1.jsonl` 可复现生成。
3. 10-step SFT sanity 通过。
4. 至少一组 SFT run 完整结束。
5. train loss 有下降趋势（完整 SFT：最后 20% steps 的 moving average < 最前 20% steps 的 moving average；sanity 只要求可记录）。
6. format_adherence 相比 baseline 提升。
7. pass_at_1 或 answer_extraction_success 没有明显退化。
8. 至少 20 条样例 diff 被人工审阅并分类。
9. 训练耗时、tokens/sec、peak memory 被记录。
10. run_report 能解释本次 SFT 学到了什么、没学到什么、下一步是否进入 DPO。

## Step 1：Math 数据协议与 toy eval

### 目标

先不下载大数据，定义统一样本格式、answer extraction、format checker、pass/fail 判定。用 5–20 条手写 toy samples 跑通 eval_math.py。

### 任务

1. 定义 Math 样本 schema：
   - `problem`（题目文本）
   - `answer`（标准答案，用于判分）
   - `level`（难度等级，1-5）
   - `source`（数据来源）
   - `domain`（子领域，如 algebra、geometry）

2. 实现 answer extraction：
   - 从模型输出中提取 `\boxed{}`、`<answer>` 标签或纯数字答案
   - 处理 LaTeX 格式、分数、小数
   - 返回 `(extracted_answer, extraction_success)`

3. 实现 format checker：
   - 检测 `<think>` 标签存在性（支持大小写变体、前后空格）
   - 检测 `<think>` 与 `</think>` 配对
   - 检测答案是否在 `</think>` 之后
   - 返回 format_adherence 分数（0 或 1）

4. 实现 pass/fail 判定：
   - 答案数值匹配（允许一定容差）
   - 或字符串精确匹配（针对非数值答案）

5. 编写 `scripts/eval_math.py`：
   - 输入：模型输出 JSONL + 标准答案 JSONL
   - 输出：eval 结果 JSONL（每题含 extraction_success、format_adherence、pass、completion_length）
   - 汇总：pass_at_1、avg_completion_length、invalid_output_rate

6. 手写 5-20 条 toy samples（覆盖格式正确/错误、答案正确/错误、extraction 成功/失败）。

### 验收标准

- 执行命令：
  ```bash
  python scripts/eval_math.py \
    --predictions data/math/toy/predictions.jsonl \
    --references data/math/toy/references.jsonl \
    --output data/math/toy/eval_results.jsonl \
    --summary data/math/toy/eval_summary.json
  ```
- `data/math/toy/eval_results.jsonl` 每条记录包含：
  - `problem_id`
  - `extraction_success`
  - `format_adherence`
  - `pass`
  - `completion_length`
- `data/math/toy/eval_summary.json` 包含：
  - `pass_at_1`
  - `answer_extraction_success`
  - `format_adherence`
  - `avg_completion_length`
  - `invalid_output_rate`
- toy samples 覆盖至少 3 种格式场景和 3 种答案场景
- 产物路径固定为 `data/math/toy/`，不散落在根目录

### 风险

- answer extraction 规则过于简单导致误判
- format checker 对 `<think>` 变体不够鲁棒

### 完成定义

eval_math.py 能在 toy data 上跑通并输出完整指标。不下载模型，不碰训练。

## Step 2：数据集选择与 baseline screening 设计

### 目标

确定 OpenR1-Math 或同类数据的子集来源，定义筛选字段、难度区间、去重规则、最大样本量。

### 任务

1. 调研可用数据源：
   - OpenR1-Math（HuggingFace）
   - MATH 数据集
   - GSM8K
   - 其他开源 math reasoning 数据

2. 对每个数据源检查 license 和可下载性：
   - license name、url
   - redistribution_allowed、commercial_use
   - source_url、access_method、requires_auth

3. 定义筛选规则：
   - 难度区间：Level 2-5（基于 baseline screening 结果调整）
   - 答案类型：优先数值答案（便于自动判分）
   - 去重：按 problem 文本去重
   - 最大样本量：5K-10K（SFT），500-1K（eval）

4. 定义数据 split：
   - train：SFT 训练集
   - val：训练过程验证
   - test：最终评估
   - review：样例审阅集（20-50 条，人工检查）

5. 编写 `data/math/manifest.yaml`：
   - 记录数据源、版本、license、下载信息、筛选规则、split 比例、样本数

6. 编写 `data/math/baseline_screening/screening_plan.md`：
   - 筛选目标（难度区间、领域分布）
   - 筛选方法（字段过滤、去重、抽样）
   - 验收标准（样本数、分布、质量检查）

### 验收标准

- `data/math/manifest.yaml` 存在且包含：
  - `sources`（数据源列表，每条含 license 和 download 信息）
  - `splits`（train/val/test/review 定义）
  - `filter_rules`（筛选规则）
  - `expected_counts`（预期样本数）
- license 字段示例：
  ```yaml
  license:
    name: "Apache-2.0"
    url: "https://www.apache.org/licenses/LICENSE-2.0"
    redistribution_allowed: true
    commercial_use: true
  download:
    source_url: "https://huggingface.co/datasets/open-r1/OpenR1-Math"
    access_method: "huggingface_hub"
    requires_auth: false
    local_cache_path: "data/math/sources/openr1_math"
  ```
- `data/math/baseline_screening/screening_plan.md` 存在且包含：
  - 筛选目标
  - 筛选方法
  - 验收标准
- SFT 训练集、验证集、样例审阅集的构造规则明确

### 风险

- 数据源 license 限制
- 难度标注不一致
- 去重不彻底导致数据泄漏

### 完成定义

manifest.yaml 和 screening_plan.md 完成，数据来源合规，构造规则可被第三方复现。

## Step 2.5：依赖与模型加载 smoke test

### 目标

在 Step 3 之前验证 MLX 环境和模型加载能力，避免模型加载失败污染 baseline eval。

### 任务

1. 验证依赖安装：
   ```bash
   python -c "import mlx; import mlx_lm"
   ```

2. 编写 `scripts/smoke/load_model.py`：
   - 加载 Qwen3-0.6B（MLX 格式）
   - 生成少量文本（max_new_tokens=16）
   - 记录加载时间、内存占用、是否成功

3. 运行 smoke test：
   ```bash
   python scripts/smoke/load_model.py \
     --config configs/qwen3_0_6b/sft_math.yaml \
     --max-new-tokens 16
   ```

4. 生成 `docs/feasibility_reports/qwen3_0_6b_load_smoke.md`：
   - 环境信息（Python、MLX 版本、OS）
   - 加载结果（成功/失败）
   - 加载时间
   - 内存占用
   - 生成的样例文本
   - 失败时的错误信息

### 验收标准

- `python -c "import mlx; import mlx_lm"` 不报错
- `scripts/smoke/load_model.py` 能加载模型并生成文本
- `docs/feasibility_reports/qwen3_0_6b_load_smoke.md` 存在且包含上述字段
- 如果加载失败，smoke.md 记录错误信息，不继续 Step 3

### 风险

- MLX 安装失败
- 模型下载超时
- 内存不足

### 完成定义

MLX 和模型加载验证通过，smoke report 生成。失败则记录问题并停止。

## Step 3：Qwen3-0.6B 推理 baseline

### 目标

下载模型后只做推理，不训练。跑小规模 Math eval，记录原始格式遵循、答案抽取成功率、pass@1、completion length。

### 任务

1. 下载 Qwen3-0.6B（MLX 格式或 transformers 格式）。
2. 实现推理脚本：
   - 加载模型
   - 应用 chat template
   - 生成 completions
   - 控制 max_new_tokens
3. 在 screening 选出的 test set 上跑推理（可先小批量，如 50-100 条）。
4. 用 Step 1 的 eval_math.py 评估输出。
5. 创建 baseline run：
   - 用 registry 创建 run
   - 冻结 config
   - 写入 eval metrics
   - 写入 hardware snapshot
   - 生成 run report

### 验收标准

- 模型能加载并生成文本
- chat template 正确应用
- eval_math.py 能评估模型输出
- baseline run 目录包含：
  - `config.yaml`
  - `run_meta.yaml`（status=completed）
  - `metrics/eval_metrics.jsonl`
  - `metrics/hardware_log.jsonl`
  - `samples/sample_diff.jsonl`（空或 baseline 样例）
  - 5 个文档骨架
- baseline 指标被记录：
  - format_adherence
  - answer_extraction_success
  - pass_at_1
  - avg_completion_length
  - invalid_output_rate

### 风险

- 模型下载失败或格式不兼容
- MLX 内存不足
- chat template 与 Qwen3 不匹配

### 完成定义

baseline eval 完成，指标可解释，run 目录完整。不训练。

## Step 4：SFT 数据构造

### 目标

把 Math 数据转成 chat format 和目标输出格式，控制 sequence length、过滤异常样本、保留 source metadata。

### 任务

1. 定义目标输出格式（配置化，不硬编码）：
   ```yaml
   format:
     reasoning_style: think_tags
     final_answer_style: boxed
     target_template: |
       <think>
       {reasoning}
       </think>
       \boxed{{{answer}}}
   ```

2. 编写数据转换脚本 `scripts/prepare_math_data.py`：
   - 读取原始数据
   - 构造 messages（system/user/assistant）
   - 根据 `format.target_template` 构造目标 completion
   - 控制 sequence length（截断或过滤）
   - 过滤异常样本（空答案、过长题目、格式错误）
   - 保留 source metadata

3. 生成 `data/math/splits/sft_v1.jsonl`：
   - 每条记录：messages、target、metadata

4. 生成数据报告：
   - 样本数
   - 平均长度（prompt、completion、total）
   - 答案可抽取率
   - 格式合法率
   - 截断比例
   - source 分布
   - level 分布

### 验收标准

- `sft_v1.jsonl` 存在且可被加载
- 数据报告存在且包含上述字段
- 样本数在预期范围内（5K-10K）
- 平均 completion length 可控（不超过 max_seq_length）
- 格式合法率 > 95%
- 答案可抽取率 > 95%
- 目标格式由配置决定，不硬编码在脚本中

### 风险

- 原始数据质量差导致过滤后样本不足
- `<think>` 格式与模型 chat template 冲突
- sequence length 截断导致信息丢失

### 完成定义

sft_v1.jsonl 可复现生成，数据报告完整，质量指标达标，格式可配置。

## Step 5：10-step SFT sanity

### 目标

接入 MLX/LoRA 后只跑 10 step，验证 chat template、LoRA target module、loss、checkpoint、eval、日志链路。

### 任务

1. 安装 MLX 和 mlx-lm（或相关训练库）。
2. 编写 `scripts/train_sft.py`：
   - 加载模型和 tokenizer
   - 应用 LoRA（r=32, alpha=32）
   - 加载 SFT 数据
   - 训练 10 steps
   - 每 step 记录 train loss
   - 保存 checkpoint
   - 运行 eval
   - 生成 sample diff
3. 配置 `configs/qwen3_0_6b/sft_math.yaml`：
   - 确认 LoRA target modules
   - 确认 learning rate、batch size、gradient accumulation
   - 确认 max_seq_length
   - 确认 format.target_template
4. 运行 sanity：
   - `python scripts/train_sft.py --config configs/qwen3_0_6b/sft_math.yaml --max-steps 10`
5. 检查：
   - loss 能记录
   - checkpoint 写入
   - eval 能跑
   - sample diff 能生成
   - 失败也能写 failure note

### 验收标准

- 10-step 训练不报错完成
- train_metrics.jsonl 包含 10 条 loss 记录
- checkpoint 目录存在且非空
- eval_metrics.jsonl 包含评估结果
- sample_diff.jsonl 包含至少 1 条样例
- hardware_log.jsonl 包含训练环境快照
- run_meta.yaml status = completed（或 failed 且有 error.txt）
- **sanity 阶段不要求 loss 下降，只要求可记录**

### 风险

- MLX 安装失败
- LoRA target module 不匹配导致训练无效
- 内存溢出
- chat template 导致格式错误

### 完成定义

10-step sanity 通过，所有链路可记录、可检查。失败也能诊断。

## Step 6：正式 0.6B Math SFT 小实验

### 目标

用 5K–10K 级别子集或更小先跑第一组完整实验。

### 任务

1. 使用 Step 4 生成的 `sft_v1.jsonl`。
2. 调整 config：
   - num_epochs：1-3
   - batch_size：根据内存调整
   - learning_rate：5e-5
3. 运行完整训练：
   - `python scripts/train_sft.py --config configs/qwen3_0_6b/sft_math.yaml`
4. 训练过程中监控：
   - loss 曲线
   - tokens/sec
   - peak memory
5. 训练后评估：
   - 在 test set 上跑 eval
   - 对比 baseline 指标
6. 样例审阅：
   - 从 review set 中抽 20-50 条
   - 对比 before/after
   - 分类：improved、regressed、malformed、unchanged
7. 生成 run report：
   - 学到了什么
   - 没学到什么
   - 下一步是否进入 DPO

### 验收标准

1. train loss 有下降趋势：**最后 20% steps 的 moving average < 最前 20% steps 的 moving average**。
2. format_adherence 相比 baseline 提升（绝对值提升 > 5% 或相对提升 > 20%）。
3. pass_at_1 或 answer_extraction_success 没有明显退化（下降 < 5%）。
4. 至少 20 条样例 diff 被人工审阅并分类。
5. tokens/sec、peak memory、wall time 被记录。
6. run_report 能解释本次 SFT 的效果和下一步决策。

### 风险

- loss 不下降（数据质量、学习率、LoRA 配置问题）
- format_adherence 不提升（格式与 chat template 冲突）
- eval 退化（过拟合、数据泄漏）
- 训练时间过长（本地资源限制）

### 完成定义

完整 SFT run 结束，指标可解释，样例审阅完成，run report 能支撑进入 DPO 的决策。
